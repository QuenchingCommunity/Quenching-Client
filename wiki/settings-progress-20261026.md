# 标准／对战模式切换进度（2026-10-26）

当前植被切换行为以文末“恢复删除后重新解压”为准；前面的目录替换、逐文件事务和来源复用属于此前方案记录。

原流程在 `saveModSettings` 保存配置时上报8%，之后调用 `mdl:update-lighting` 等待全部着色器／环境／DNC处理完成。该IPC未转发进度，后续地形、树木和效果设置也没有阶段报告，界面因此长时间停在8%。

现在 `syncLightingResources` 按真实阶段报告：选定着色器ZIP扫描／解包、资源文件检查与复制、公共环境解包／复制、DNC恢复与逐文件亮度处理、着色器替换和最终整理。`withShaderBundle` 转发既有ZIP进度；受管文件同步在每个删除／比较／复制完成后计数；DNC在每个MDL处理完成后计数。

光照IPC通过既有 `mod:profile-progress` 通道携带 `operation: lighting` 与请求ID。preload转发到既有DOM事件，设置hook只接受当前请求，映射到整套预设的12～65%，为地形、树木、植被和着色器开关保留后续区间。首页忽略未经hook映射的光照事件。完整设置成功才到100%；失败／超时移除监听，旧请求不能推进新操作。报告按整数百分比去重并保持单调，不用计时器模拟进度。

完整画质配置切换也复用底层进度，映射到其资源同步区间。包含完整配置切换的保存不再重复执行相同光照同步。

验证：`test-lighting-progress.ts` 检查真实ZIP解包、工作尚未完成时的IPC消息、请求标识及失败不报100%；`test-managed-resource-files.ts` 检查删除和复制完成后的计数；`test-graphics-settings-transition.ts` 覆盖标准／对战完整设置进度、旧请求忽略、失败清理和最终完成；`test-startup-rendering-files.ts` 检查实际隔离落盘与各阶段；`test-dnc-level3.ts` 验证250份光照结果。

本次更新源码和本地dist构建，未生成新的便携EXE／ASAR，也未上传网络更新。

## 对战切回标准的地形超时修复

晚间运行日志显示光照从 battle 切到 standard 约耗时 0.7 秒；地形 SLK 随即完成，最后停在 `zip-foliage-que.zip` 的植被替换。设置 hook 对整次地形 IPC 设有固定 45 秒期限，但超时不会取消主进程的删除／解压，配置却会被恢复成旧预设。之后同一预设还会再次调用植被解压。

该包压缩后 52,211,738 字节，展开为 176 个文件、181,330,472 字节。使用真实包在 `_tmp/preset-timeout` 隔离复现：原 JavaScript 流式解压耗时 115,795 ms；修复后经完整植被服务从 v16 切至 latest 为 3,570 ms，再次应用相同包为 8 ms。耗时是本机单次隔离测量，不是所有硬盘的性能承诺。

- 植被 ZIP 使用客户端已有的完整 7-Zip 工具批量解压，先验证并解到同卷 `_tmp/foliage-*`，完整后替换生效目录。解压失败保留旧目录，替换失败还原旧目录；恢复失败保留备份路径。安装来源记录包括包名、大小和修改时间，相同来源不重复解压。
- 地形／植被 IPC 携带各自的 operation 和 requestId，实时进度通过原通道转发。hook 将它们映射到整次预设进度并清理监听；首页不直接使用子操作的百分比。地形已同步植被时，不再重复执行独立的开启植被调用。
- 移除这两个 IPC 的前端固定总时限，持续等待主进程结果，不再因前端计时结束而放开控件、恢复配置，同时留下后台写入。植被原生解压改用 90 秒无输出保护：真实输出续期；无响应时先终止解压进程、等待退出，再向上返回失败。此设置不改变完整包 RAR／7z 等其他入口的默认时限。

验收：`scripts/test-foliage-sync.ts --real` 使用真实包验证切换及复用，并测试损坏包保留旧植被、目录提交失败回滚和暂存清理；`scripts/test-archive-idle.ts` 检查真实工作活跃时续期、空闲时先停止 worker；`test-graphics-settings-transition.ts` 压缩旧 45 秒时限，验证慢地形工作未结束时仍保持忙碌、旧请求不推进进度，以及预设只同步一次植被。既有地形／水面、RAR／7z 回归继续通过。

## Windows 目录占用的后续修复

23:20:58 的实际错误为将 `environment/foliage` 改名到暂存备份时返回 EPERM；23:21:43 再次尝试返回 ENOENT，23:21:59 第三次应用成功。这是整目录改名失败，不能与前端固定超时混为一谈。现有日志没有占用进程信息，无法证明历史占用者是客户端、游戏或其他进程。

解压器仅访问压缩包和同卷暂存目录，代码等待其 close 后才提交植被；客户端没有把活动 foliage 设为工作目录或显式长期监视该目录。但前台 IPC 原本保留并发能力，因此同一活动目录的跨入口操作仍需要单独协调。

Windows 下已有植被目录现在始终保留原位，通过既有文件事务比较并更新变化文件，避免先尝试可能长时间被阻塞的整目录 rename。写入前备份，失败恢复已触及的文件；来源标记最后提交，恢复失败保留备份。POSIX 保留目录替换，并为目录占用提供同样的文件事务后备路径。源目录在提交前已经消失时允许安装准备好的新目录。

植被开关、地形联动及启动处理在异步路径探测前排队，按请求顺序执行；活动 foliage 的文件更新与 HD 环境停放／还原共享目录锁，防止客户端自身同时搬移、删除或更新同一目录。锁不阻止其他进程访问文件。

新增真实 Windows 占用测试：辅助进程使用不允许 FILE_SHARE_DELETE 的目录句柄，并验证删除访问被拒绝，持有句柄期间完成植被逐文件切换。测试还覆盖部分写入后回滚、来源标记最后提交、FIFO 并发、环境搬移等待及旧着色器事务回归。真实资源包切回标准的本机隔离测量为 3,989 ms，同包复用为 4 ms；未对玩家正在使用的分支做自动切换测试。

## 恢复删除后重新解压

用户明确要求恢复旧逻辑：每次应用植被时先删除活动 `environment/foliage`，等待删除成功，再重新解压所选完整 ZIP。已撤掉活动目录改名、逐文件事务替换和来源标记复用；重复选择同一个包也会重新解压。保留快速原生解压、真实进度、90 秒无输出保护，以及植被操作与环境搬移的串行协调，不恢复前端固定总时限。

解压包路径不存在时会在删除前报错；删除失败立即停止，不开始解压。删除成功后若压缩包损坏，不保留旧植被，这是恢复删除后解压的行为，不再宣称有目录回滚。

`scripts/test-foliage-sync.ts` 已按当前行为更新，验证删除早于解压、重复应用重建被改动文件、旧变体文件清除、不调用活动目录 rename、删除失败停止、缺包／坏包处理、进度、FIFO 和环境搬移协调。真实包在隔离目录从对战切回标准，本机单次删除加解压耗时 1,780 ms。当前仅测试隔离副本，没有自动删除玩家正在使用的植被目录。
