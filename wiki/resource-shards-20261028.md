2026-10-28 按用户要求，将客户端内原来的约 100 MB 单一资源归档拆成五个大小接近的独立 7z。这不是外层客户端便携包拆分，也不是分卷；五包没有共享字典，任意一个包都可以单独解压到空目录。

## 固定分组与构建

分组函数在 `src/shared/bundled-resource-paths.mjs`。按包路径及素材类型固定归属，不按每次构建的文件体积自动重新均分，避免一次小修改引起其他包变化。后续新增大量素材造成明显不均衡时，再显式调整映射。

`prepare-client-assets.mjs` 仍是 electron／start／build／pack／dist 和 beforePack 的公共准备入口。每包有自己的内容 ID、SHA-256、大小和逐文件摘要；源不变时保持包字节和修改时间不变，源变化时只更新对应包内变化成员。

首次拆分复用原非固实归档中已有压缩流，没有修改同事的着色器源文件。发布五包与清单采用可恢复事务，最后提交清单；中途失败会恢复已替换的包。后续开发源仍然直接读取展开目录。

## 运行期和兼容

资源清单升级为 schema 3，逐文件记录所属归档。启动只读取、校验元数据；请求某素材时只校验它所属的归档并提取所选成员，另外四包缺失不会阻止读取本包。缓存仍按总内容 ID 隔离，不进入客户端官方文件快照。

客户端保留 schema 2 单包资源清单的读取兼容。UI 公共层先于版本 FDF 的顺序不变；植被的逻辑资源组可跨颜色／材质两个物理包取成员，保持既有删除后重装流程及原文件路径。

Windows 和 Mac 分发／便携导出规则均改为明确的五个文件名，不带旧单一资源包、旧 ZIP 或 `assets/unpacked` 本体。图标、公钥、基础配置等启动必需小文件继续直接读取。

## 自动更新含义

现有客户端 schema 2 自动更新按文件 SHA-256 比较。五包是五个独立目标文件；只修改着色器时，只有核心资源包和相应资源清单改变，另外四包不需要下载。已存在且与目标摘要相同的包可本地复用。

第一次从单包方案迁移，需要新的客户端代码、schema 3 资源清单和五个新命名包一同交付；这一次需要全套资源。之后更新按变化包传输。安装中残留的旧单包不被新 schema 3 使用；本次没有添加未经所有权校验的安装目录删除逻辑。

本次只完成本地资源生成和客户端源码改造，**未重新制作客户端便携包、未上传、未部署正式／测试更新清单**。不能据此声称线上客户端已经使用五包。
