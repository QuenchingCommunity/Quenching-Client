# r9.7：进程选择与地图缓存

本版为独立测试组件，基于保留的 r9.6，不涉及 QM 自动更新。

## 已确认的问题与修复

本机系统列出 PID 1620、27308、49092 三个 Warcraft III 同名条目，但其路径、版本均为空，HandleCount 为 0。旧代码先数进程，得到“多个魔兽”；现在先排除不可识别的条目。无可用实例时提示启动游戏；多实例时按配置目录和支持版本筛选，再稳定选择 PID 最小的一份。显式测试 PID 仍优先且不自动改选。每次操作重新检测，不永久保存运行期 PID。

选定 PID 通过 War3Session.connect 的局部参数传入原生发现子进程，覆盖该子进程的测试 pin，不修改主进程环境；返回其他 PID 会拒绝连接。发布本地节点、入局及结算继续使用同一实例。未为此另开或关闭魔兽。

以前房主每次开始都会 POST 完整地图，服务端读完校验后才发现 SHA-256 已有并复用。因此客户端确实重复上传，但服务器不会每次另存一个副本。

新增鉴权 GET `/match-player-301-lab/maps/{sha256}/metadata`，只返回已存在且文件大小符合的地图元数据。客户端先查询并校对原生地图字段，命中后不读取上传文件内容、不 POST；仅缺失时上传。旧服务器缺少该路由时兼容回退原上传方式。网络／鉴权失败不会被误当成缺失。服务端还修复了容量达到上限时重复地图也被误拒绝的问题；二进制文件丢失时允许重新上传修复，不重复累计容量。

界面分别显示“正在核对服务器地图”“已复用服务器地图”“正在上传新地图”。没有游戏时在地图传输前结束操作。

## 服务器核验与部署

主机 191.40.44.138（QMCN1），域名 qmapi-cn1.txzy.net。地图仓库 16 个文件组成 8 张不同 SHA-256 地图，总计 38,128,536 字节；8 张地图内容哈希均正确，没有临时上传、孤立二进制或重复内容条目。删除数量为 0，保留有效缓存，避免用户重新上传。

无活动对局、无等待玩家时部署 `/opt/quenching-match-player-301-lab/releases/20261030-process-map-cache`，仅更新 remote-duel-node.mjs、room-map-store.mjs 并重载匹配服务。回滚 release 为 20261029-map-slot-editor。没有修改 Nginx、QUIC sidecar 或有效地图文件。

## 验收

- 86 项回归通过，包括 3 个空路径残留、多个正常实例自动选择、目录／版本筛选、显式 pin、同一 PID 的真实 PowerShell 子进程传递及不污染主进程环境。
- HTTP 实测首次上传一次，重复使用及重启服务后不上传；缺失二进制可修复；元数据冲突和服务器故障不会触发盲目上传；临时上传文件正常清理。
- 打包后客户端在当前电脑上检查时准确提示“请手动打开魔兽，停在主菜单或局域网列表”，没有触发地图上传。
- 公网已部署接口连续查询已有 Glory Hills 两次，上传 0 次、读取上传文件内容 0 次。
- GUI 两局模拟匹配、可编辑／只读槽位及数字昵称保留通过。

本轮没有重新进行真实双端开局，不将自动化／接口测试描述为新的双端实机证明。r9.6 已有的槽位及正常结算实机记录继续保留；数字昵称目视确认、特定 DotA 载入与延迟尖峰的未解决事项仍适用。

## 使用

完整包解压运行「淬火匹配测试-自有服务器.exe」。r9.6 用户退出匹配工具后覆盖 r9.7 的 update.zip 即可，无需关闭魔兽。其他旧版本使用完整包。
