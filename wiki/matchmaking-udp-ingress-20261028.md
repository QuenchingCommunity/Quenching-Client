## 为什么面板没有拦截仍会这样

面板的安全组/黑白名单是规则链中的一层。宿主机、虚拟交换机、上游 ACL 或 UDP 防护策略可能独立存在；规则也可能没有同步到实际转发层。本次更符合这些方向，但没有宿主机和上游抓包，不能认定具体哪一项或哪一家设备有故障。

主机 INPUT 链默认 drop 与用户规则中的 UDP 443 accept 同时存在是正常 UFW 结构，不能看到一个 policy drop 就说端口没有放行。通常主机 INPUT 防火墙丢包仍能在 ens18 入站抓包看到；本次连网卡都没见到，故继续改 UFW、关闭整个防火墙或修改 QUIC 拥塞参数都缺乏依据。

## 处理路径

1. 请机房核对该 IP 的**外部新建 UDP 入站**，目的端口 443，检查宿主机/虚拟交换机/防护设备和转发策略，不只重复查看面板空规则。
2. 机房处理后，原地复测：外部真实 QUIC 握手、证书验证、入局前预检均应通过，随后再做异地双端对局验收。仅有 UDP 扫描显示 `open|filtered` 不算通过。
