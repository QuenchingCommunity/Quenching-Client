# r9.8 连接模式

独立匹配组件新增三选一：自有服务器、纯局域网、Battle.net。默认保留自有服务器方式，没有整合到 QM，也没有变更 QM 自动更新。

## 数据路径

| 模式 | 玩家发现／撮合／地图 | 游戏主机与流量 |
| --- | --- | --- |
| 自有服务器 | qmapi-cn1.txzy.net | 远程 W3GS 节点，QUIC 或 WSS |
| 纯局域网 | 自有 UDP 发现及局域网 HTTP | 房主工具内的 DuelSession，两端通过本地桥接接入房主的局域网 TCP／WebSocket；不连接公网节点 |
| Battle.net | qmapi-cn1.txzy.net 协调 | 原生 BNET 提供器，房主 CreateLobby、客人按分配名称加入；自有服务器不接收本局 W3GS 流量 |

局域网做成了包括发现与匹配在内可离线工作的方式。发现 UDP 34855，房主动态 TCP 端口承担 HTTP 和游戏流量；IPv4 私有网络，需要私有网络防火墙放行，不需要 Bonjour 或公网端口转发。房主必须保持工具运行。

Battle.net 需要双方正常启动、登录并位于同一战网地区；offline.exe 的网络隔离启动不能用于该模式。游戏中使用战网账号名。现在只核对原生大厅实际位置，没有实现任意真人位置交换；位置与所选配置不一致会停止，避免错误开局。电脑、开放／关闭、阵营和种族通过原生指令设置并核对。其余地图特殊限制仍需实测，不能宣称与自有节点的全部槽位能力等价。

## 源码与兼容

- `connection-modes.mjs`：node/lan/bnet 枚举，旧请求缺省 node。
- `lan-match-service.mjs`：UDP 发现、受限局域网端点及本机主机。服务绑定所有 IPv4 接口，独立随机访问令牌，通过局域网发现供同网段玩家使用。
- `direct-match-room.mjs`：Battle.net 协调状态机。没有 W3GS attach；只有 host-ready、ready、loaded、finished。两端完成后保存来自客户端原生结算的结果；不伪造无数据的胜负。直接模式客户端失联有 45 秒过期保护。
- `remote-duel-node.mjs`：模式隔离的房间列表、加入门禁和阶段上报。旧客户端只看 node 房间；跨模式加入被拒绝。公网服务允许 node/bnet，本地局域网服务只允许 lan。
- `native-lobby-slots.ts` 与 `warcraft-adapter.ts`：接回既有 Battle.net 提供器／原生建局路径，设置并检查大厅位置。SetTeam／SetRace／OpenSlot／CloseSlot／SetComputerSlot 的名称和参数来自已有本地原生 WebUI 代码。
- `player-301-gui-worker.ts` 与 `PlayerClient.cs`：模式保存、房间查询、局域网服务生命周期以及执行分支。局域网报告保留本机，不向公网发送诊断。

服务端部署到 191.40.44.138，release `/opt/quenching-match-player-301-lab/releases/20261101-connection-modes-r2`，前一版及 r1 保留用于回滚。只在无活动对局和无等待玩家时重载匹配服务，未修改 Nginx、QUIC 服务及地图缓存。

## 验证及边界

107 项回归通过。包括既有 W3GS、地图、种子、昵称与生命周期，以及新增模式隔离、直接模式的就绪顺序／角色权限、实际 UDP 发现、实际两条 TCP/W3GS 操作同步、原生大厅指令计划与位置核对。原生适配器既有测试通过，但使用的是模拟游戏事件。

打包客户端在公网服务地址故意设为不可达时，仍通过实际 UDP 和 HTTP 找到本地局域网房间、读取匹配地图和槽位配置，并完成三个模式的设置往返。GUI 识别三个选项，可编辑／只读槽位、两次模拟匹配及昵称保留通过，截图已目视检查。

公网 Battle.net 协调测试完成实际 HTTPS 建房、列表隔离、加入、主机／双方就绪、加载及结束阶段；没有连接游戏 wire，未上报胜负或伪装成真实魔兽。测试对局为 `fbac5198-09bd-40fc-8695-3d786421c052`，instance `cb4fbbdc-aec9-46a4-840b-59f917f24a25`。

**当前没有可用魔兽进程，没有额外启动或关闭游戏。两个新增模式尚未做当前版本双人实机复测。** r9.6 的真实节点对局证据保留，但不能代替新增模式的实际开局、聊天和结算验证。特别是 Battle.net 登录地区、当前版本原生字段、复杂 RPG 位置及同网段两台 Windows 的防火墙，需要玩家实测。包体和说明明确标注此边界。

## 建议实机顺序

1. 两台同网段电脑选纯局域网；先验证断开公网后仍能发现并入局，再核对工人操作、聊天、所选位置和结算。房主保持工具运行。
2. 正常战网启动、同区两个账号选择 Battle.net，以默认真人位置的对战地图验证，再验证电脑槽位与自定义地图。
3. 最后回归自有服务器模式，并导出双方报告核对 connectionMode、transport、gameId、原生事件及结算。
