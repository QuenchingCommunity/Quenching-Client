# 媒体像素格式日志与主题加载修复

用户反馈 Chromium／FFmpeg 输出八条 `Unsupported pixel format: -1`。该日志来自客户端媒体层；不是 Warcraft 光照或游戏 shaders 的错误。`-1` 表示 FFmpeg 未提供已确定的像素格式，单凭此日志不能判断文件损坏或播放失败。Chromium 对未识别的格式会从格式转换函数输出此日志，见 [Chromium 源码](https://chromium.googlesource.com/chromium/src/+/refs/tags/132.0.6834.162/media/ffmpeg/ffmpeg_common.cc#864)。

## 调查证据与边界

读取当前用户主题配置为内置 magicstorm，没有自定义主题。七个内置 MP4 为 AVC／H.264。使用项目当前 Electron 33.1.0，在独立用户数据目录实际加载并播放所有视频，七个均产生解码帧，readyState=4；没有出现像素格式日志。另检查仅加载元数据和三份音效，同样没有复现该日志。没有转码或覆盖原视频，没有更换 FFmpeg DLL，也没有关闭客户端全局 GPU 加速或屏蔽原生日志。

这意味着尚未复现用户原先八条日志的唯一触发条件，不能声称已经证明素材损坏，或证明所有机器都不会再出现该底层探测日志。源码调查同时发现以下可确认的主题加载问题，已实际修复。

## 已修复

- 同一主题使用相对文件名与已解析绝对 URL 比较，导致重复选择仍重新加载；现在统一 URL 后比较，重复主题零重新加载。
- Windows 自定义视频路径被当作网页相对路径，中文、空格、`#`、`%` 可能解析错误；现在保留完整远程 URL，并将本地绝对路径正确编码为 file URL。
- 淡入切换先 load 再绑定 canplay，可能错过事件；改为先绑定监听器后指定来源。异步播放和配置读取有失效保护，清理监听器与淡入计时器，过期请求不会覆盖新选择。
- 切换完成后释放旧视频来源，保留当前视频解码器；新的主题加载失败时保留当前主题。
- 当前背景加载失败时只尝试默认主题回退，默认主题也失败则停止加载并保留静态黑色背景，不连续重试。
- 主题页关闭后不保留预览媒体；缩略视频改为 preload=none，仅播放悬停项，避免同时预加载全部高清主题。
- 增加具体来源、MediaError 代码／消息及 readyState／networkState 日志，供原始告警再次出现时关联判断；没有过滤或吞掉 Chromium 错误。

## 验证

`test-theme-media.ts` 使用实际 BackgroundVideo 组件，通过 esbuild 浏览器构建并在真实 Electron 中运行：初始画面解码、重复主题不重载、切换后解码、淡入后旧来源释放、无效新主题保留当前画面均通过；同时检查 Windows／中文／特殊字符路径及开发 HTTP URL。原生 stderr 没有像素格式告警。

测试入口 `yarn test:theme-media`。本次记录位于 `_tmp/media-pixel-format-20261029/`：七个内置视频的实际播放结果在 `probe-native.log`，最终组件回归在 `tests-final.log`／`component-native.log`。生产编译日志为 `build.log`。

最终 `yarn run build` 通过，总计 43.34 秒，资源未变化、未重压。隔离探测的浏览器用户目录已移到回收站，组件测试的大体积临时目录已自动清理，保留小型报告。
