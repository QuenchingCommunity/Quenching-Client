# 2026-10-28 构建耗时调查

后续同日已改为统一 `resources.7z` 与展开源，独立 shader ZIP 准备逻辑不再执行。本文保留当时的测量与排查经过；当前流程见 `quenching-resource-inventory-20261028.md`。

用户报告完整命令 545.29 秒，仅有末尾签名跳过日志；该日志不足以定位当次各阶段耗时。本机单独执行资源准备与 webpack，并重跑完整 `npm run dist:win`，未复现 545 秒。Windows 包仍使用 Electron 33.1.0，版本为 3.7 TEST。

## 确认并修复的额外开销

`prepare-shader-bundles.mjs` 原来每次读取 548,272,929 字节源文件并以 DEFLATE level 9 全量压缩，然后才比较旧 ZIP 判断无需写入。单独测得 26.745 秒。现在先核对 ZIP CRC、文件集合与每个源文件的真实内容，完全一致则复用旧包；单独测得 10.141 秒（脚本内部 9.321 秒）。不依赖大小或修改时间；同大小同时间的修改、增删改名、损坏／缺失 ZIP 都会重建。

复用前后 `assets/quenching/shaders.zip` 均为 45,413,068 字节，SHA-256：`a73094254d69ceb92a0de67a1fff7b5a965314a38f8db70fc8428d90e4c5f814`，没有重写包。3.0 独立包仍仅由原有显式 `--legacy-source` 入口生成。

`scripts/webpack.build/index.ts` 增加各目标和总耗时输出；构建出错时返回非零退出码。没有通过关闭生产压缩、更换 Electron 或删减运行时内容提速。
